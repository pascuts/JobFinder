# Security & Licence Enforcement Policy

This document outlines the policies and procedures for reporting **security vulnerabilities** as well as **unauthorised commercial misuse, header tampering, or licence violations** relating to this project.

---

## 1. Reporting Security Vulnerabilities

We take the security and privacy of our code and users seriously. If you discover a security vulnerability (e.g. credential exposure risks, data leakage, injection vulnerabilities, or third-party API token risks), please report it responsibly.

### A. Supported Versions
| Branch / Version | Supported |
| :--- | :--- |
| `main` (Latest commit) | ✅ Supported |
| Development / Feature Branches | ❌ Not Supported |
| Community Forks | ❌ Not Supported |

### B. How to Submit a Vulnerability Report
* **Do NOT open a public GitHub issue** or disclose vulnerabilities publicly until they have been reviewed and addressed.
* Send your report privately via email to **Adrian Pascut (ESLAMERA LIMITED)** at `[Insert Email Address]`.
* **Include in your report**:
  * A summary of the vulnerability and its potential impact.
  * Clear, step-by-step instructions or proof-of-concept (PoC) to reproduce the issue.
  * Affected file paths, functions, or API interactions.
  * Any relevant logs (ensuring no real user credentials or candidate personal data are included).

### C. Response & Resolution Timeline
* **Initial Acknowledgment**: Within **48 hours** of receipt.
* **Status Update & Assessment**: Within **5 business days**.
* **Remediation**: Patches will be developed and deployed to the `main` branch as quickly as possible.

### A. Reportable Infringements
* **Unauthorised Commercial Deployment**: A business, recruitment agency, SaaS product, or enterprise using, hosting, or bundling this software without an executed Commercial Licence Agreement.
* **Licence & Header Tampering / Stripping**: Removing, altering, or omitting the root `LICENSE` file or copyright header blocks referencing **Adrian Pascut (ESLAMERA LIMITED)** in any copy, fork, or derivative work.
* **Re-Licensing Attempts**: Attempting to distribute or publish forks under open-source licences (e.g. MIT, Apache, GPL).

### B. How to Submit a Misuse Report
Submit reports confidentially via email to **ESLAMERA LIMITED** at `[Insert Email Address]`.

Please provide as much supporting detail as available:
1. **Violating Entity Details**: Company name, domain, SaaS platform URL, or GitHub profile/repository link.
2. **Nature of Infringement**: Description of unauthorised commercial service, recruitment workflow, code resale, or header removal.
3. **Evidence**: Screenshots, repository links, direct URLs, or archived web pages showing the violation.

### C. Confidentiality Commitment
All reports of commercial misuse or licence infringement are treated with **strict confidentiality**. The identity of whistleblowers and reporters will remain confidential unless explicit consent is granted or disclosure is mandated by law.
